# eNet API (v0.4)

Локальный backend для eNet ID и каталога сервисов. **Node.js 22.16+** (встроенный `node:sqlite`; в Node 22 SQLite может выдавать предупреждение ExperimentalWarning). Внешних npm-пакетов нет.

## Запуск

```bash
cd api
node --version
node src/server.mjs
# отдельный терминал
curl http://127.0.0.1:8787/health
npm test
```

По умолчанию сервер слушает **только 127.0.0.1:8787** и хранит БД в `api/data/enet.sqlite`. Папка исключена из Git. Конфигурация: `ENET_HOST`, `ENET_PORT`, `ENET_DB_PATH`, `ENET_ALLOWED_ORIGINS` (список browser origins через запятую). `.env.example` служит справкой; переменные устанавливаются окружением, автоматически файл .env не читается.

## Маршруты

- `GET /health` публичный healthcheck с версией API
- `GET /ready` публичная проверка готовности SQLite (503, если база недоступна)
- `GET /v1/meta` публичное описание возможностей API
- `POST /v1/auth/register` JSON: `{"name":"...","email":"...","password":"..."}`
- `POST /v1/auth/login` JSON: `{"email":"...","password":"..."}`
- `GET /v1/auth/me` заголовок `Authorization: Bearer <token>`
- `POST /v1/auth/logout` тот же Bearer
- `POST /v1/auth/change-password` Bearer, JSON: `{\"current_password\":\"...\",\"new_password\":\"...\"}`; проверяет старый пароль и отзывает другие сессии
- `POST /v1/auth/logout-others` Bearer; отзывает все остальные сессии этого пользователя и возвращает `revoked`
- `POST /v1/auth/profile` Bearer, JSON `{\"name\":\"Новое имя\"}`, возвращает актуальный `user`
- `GET /v1/auth/sessions` Bearer, список активных сеансов с идентификаторами, датами и отметкой `current`
- `POST /v1/auth/sessions/revoke` Bearer, JSON `{\"session_id\":\"UUID\"}`, отключает **чужой сеанс того же пользователя**, но не текущий

При старте API автоматически добавляет поля метаданных в существующую таблицу сеансов без удаления пользователей. Названия устройств задаются клиентом и **не являются подтверждёнными данными об устройстве**.
- `GET /v1/services` защищённый каталог сервисов (пока содержит ссылку на Продайзер)
- `GET /v1/me/preferences` Bearer, избранные сервисы пользователя
- `POST /v1/me/preferences` Bearer, JSON: `{"favorite_services":["prodayzer"]}`. Не более 20 уникальных ID, только существующие сервисы.
- `POST /v1/auth/reset-password` отвечает 501 до подключения почтового провайдера

Регистрация и вход возвращают `{token,expires_at,user:{id,email,name}}`. Пароли хешируются scrypt с индивидуальной солью; сервер хранит только SHA-256 от случайных токенов сессий. Сессия действительна 7 дней, выход отзывает её. Текущую сессию можно сохранить при смене пароля, завершив остальные.

## Работа через HTTPS-прокси

Пример systemd, Caddy и резервного копирования: [DEPLOYMENT.md](DEPLOYMENT.md). API по умолчанию слушает `127.0.0.1:8787`. На сервере с Caddy можно установить `ENET_TRUST_PROXY=true`, только если порт API закрыт снаружи, а прокси **перезаписывает** заголовок `X-Real-IP`.

Ответы включают `X-Request-Id`, `Retry-After` при превышении лимитов, `Permissions-Policy` и защитные HTTP-заголовки. Вход ограничен отдельно по IP и нормализованному email; лимиты остаются локальными для процесса.

## Ограничения перед публичным запуском

1. **Не публиковать порт API в интернет без HTTPS, reverse proxy и проверки сетевых ограничений.** HTTP в localhost предназначен для разработки.
2. Нет подтверждения почты, доставки писем для восстановления пароля, MFA и OAuth/OIDC. **Это ещё не единый вход в Продайзер**.
3. Ограничение частоты запросов пока в памяти процесса. Перед публичным запуском нужны централизованный rate limit, аудит и защита от перебора по пользователю.
4. SQLite подходит для локального MVP. Перед масштабированием продумать PostgreSQL, резервные копии и миграции.
5. Никогда не добавлять файлы `data/`, секреты и токены в Git.

## Проверка

`npm test` запускает интеграционный тест реального HTTP-сервера с временной БД без внешних зависимостей.

## Несколько устройств и документация

API обслуживает клиентов Flutter для Linux, Windows и iOS. Избранные сервисы привязаны к учётной записи в SQLite и читаются на разных устройствах после входа. Пока доступен один настоящий сервис: Продайзер в режиме внешней ссылки. SSO с Продайзером отсутствует.

Описание маршрутов: [OpenAPI](openapi.yaml). Все JSON-ответы имеют заголовок `X-Request-Id` для поиска проблем в диагностике. Внешние клиенты должны использовать HTTPS с обратным прокси; публичное развертывание пока не выполнено.
