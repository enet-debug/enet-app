# eNet ID: подключение Supabase Auth

Это реальная интеграция авторизации, а не демо. Пока нет проекта Supabase и почтовой конфигурации, приложение **не будет** принимать фиктивные пароли.

## 1. Создайте проект Supabase

1. Создайте отдельный проект для eNet ID.
2. В **Authentication → Providers → Email** включите вход по email и подтверждение почты.
3. Настройте **Authentication → URL Configuration → Site URL** на свой реальный HTTPS-адрес (сейчас здесь нет готового reset-сайта). Настройте разрешённые redirect URLs только под свои домены.
4. Настройте SMTP отправителя для рабочих регистрационных писем. Проверьте лимиты и доставляемость.
5. В **Project Settings / Connect** получите **Project URL** и **publishable key**. Не используйте `service_role`, `secret` или пароль от базы в приложении.
6. Включите ограничения по частоте запросов и защиту от злоупотреблений. Проверьте настройки срока действия сессий.

## 2. Запуск Windows

В корне репозитория:

```bash
flutter create --platforms=windows,ios,web .
flutter pub get
flutter run -d windows --dart-define=ENET_SUPABASE_URL=https://YOUR_PROJECT.supabase.co --dart-define=ENET_SUPABASE_PUBLISHABLE_KEY=YOUR_PUBLISHABLE_KEY
```

Используйте реальные значения проекта. Для iOS запуск на macOS/Xcode с теми же `--dart-define`. Не помещайте секретные ключи в клиентский код: значения `dart-define` попадают в приложение и не являются тайной.

## 3. Регистрация и вход

- Регистрация сохраняет `display_name` в user metadata Supabase.
- Если включено подтверждение email, новый аккаунт не получает сессию до подтверждения; пользователь видит сообщение о письме.
- Вход по email/паролю создаёт серверную сессию; обновление сессии выполняет Supabase SDK.
- Токены сохраняются через `flutter_secure_storage`, а не открытый `SharedPreferences`.
- Выход завершает сеанс через Supabase.
- В профиле отображается устойчивый `user.id`, пригодный в качестве идентификатора eNet ID.

## 4. Сброс пароля

Запрос отправки письма реализован. **Для завершения восстановления необходимо создать безопасную HTTPS-страницу смены пароля или полноценный обработчик deep links** и задать `ENET_RESET_REDIRECT_URL` через `--dart-define`; URL должен быть разрешён в Supabase. Страница должна корректно обработать recovery-токен и вызвать `updateUser` для задания нового пароля. Без этого письмо может вести на Site URL и восстановление не будет завершено. До публичного релиза этот сценарий обязательно протестировать целиком.

## 5. eNet ID для других сервисов

Один проект Supabase может хранить пользователей с единым стабильным UUID для Продайзера, HudiGram и других продуктов. **Это ещё не полноценный SSO**: автоматический вход между независимыми сайтами/приложениями требует отдельной настройки OAuth/OIDC или согласованного backend-потока. Не передавайте access/refresh токены между сервисами вручную и не принимайте на API произвольный UUID клиента за подтверждённую личность. На серверах проверяйте JWT (подпись, issuer, audience, expiry), а доступ к данным ограничивайте RLS.

## 6. Контроль перед выпуском

- Проверить сборку `flutter analyze`, `flutter test` и Windows/iOS release.
- Протестировать регистрацию с подтверждением, вход, неверный пароль, закрытие и повторное открытие, обновление сессии и выход.
- Протестировать восстановление пароля по полному циклу.
- Настроить email deliverability, мониторинг ошибок, политику данных, удаление аккаунта.
- Не выкатывать публично без проверки серверной конфигурации, разрешений и RLS.
