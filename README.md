# eNet App

Кроссплатформенное приложение Flutter для **Windows и iOS**. Единый тёмный интерфейс eNet с матовым стеклом, живым фоном, голубыми акцентами и плавной анимацией.

## Что реализовано

- Адаптивные экраны регистрации, входа и запроса восстановления пароля.
- **eNet ID:** Supabase Auth вместо демонстрационных логинов.
- Подтверждение регистрации по email (если включено в Supabase), реальные серверные сеансы, обновление токенов, выход.
- Защищённое хранение сессии через `flutter_secure_storage` (Keychain / Windows storage).
- Постоянный `user.id` в профиле, который может использоваться как единый ID в сервисах eNet.
- Главная, уведомления, профиль, настройки; анимации и опция отключения живого фона.
- Авторизация за интерфейсом `AuthRepository`, чтобы менять провайдер без переписывания UI.

## Настройка eNet ID

**Без Supabase приложение намеренно не запускает демо-авторизацию.** Сначала создайте проект Supabase и подключите SMTP для подтверждения email.

Полная инструкция по запуску, настройкам безопасности и ограничениям восстановления пароля: **[docs/ENET_ID_SETUP.md](docs/ENET_ID_SETUP.md)**.

### Быстрый запуск

Требуется Flutter SDK 3.27+ (Dart 3.6+) и созданный Supabase-проект:

```bash
flutter create --platforms=windows,ios,web .
flutter pub get
flutter run -d windows --dart-define=ENET_SUPABASE_URL=https://YOUR_PROJECT.supabase.co --dart-define=ENET_SUPABASE_PUBLISHABLE_KEY=YOUR_PUBLISHABLE_KEY
```

Для iOS необходимы macOS и Xcode. Нативные папки в минимальном репозитории генерируются командой `flutter create`.

## Архитектура

- `lib/core/theme`: цвета, темы и параметры движения
- `lib/core/widgets`: компоненты интерфейса
- `lib/features/auth/domain`: модель eNet ID, интерфейс репозитория
- `lib/features/auth/data/supabase_auth_repository.dart`: подключение сервера авторизации
- `lib/features/auth/data/secure_session_storage.dart`: безопасное хранение токенов
- `lib/features/auth/application`: состояние сессии
- `lib/features/auth/presentation`: вход, регистрация и восстановление
- `lib/features/shell/presentation`: главный интерфейс

## Статус и ограничения

Серверные аккаунты будут работать только **после настройки проекта Supabase**. Отправка письма для восстановления реализована, но для завершения смены пароля требуется реальная HTTPS reset-страница либо обработчик deep links. Одна база пользователей даёт общий eNet ID для продуктов, но автоматический SSO между независимыми приложениями потребуется проектировать отдельно.

Перед публичным релизом нужны полные интеграционные проверки авторизации, SMTP, восстановления, проверки JWT на серверах, RLS, политик хранения данных и удаления аккаунта. Никакие служебные секреты Supabase нельзя размещать в клиентском Flutter-коде.
