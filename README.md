# eNet — кроссплатформенное приложение + API + eNet ID

Монорепозиторий экосистемы eNet:

- `lib/`: Flutter-приложение для Linux, Windows и iOS (также совместимо с Android и macOS при наличии соответствующего runner).
- `api/`: локальный HTTP API с настоящими учётными записями, SQLite, сессиями и каталогом сервисов.
- `.github/workflows/enet-linux.yml`: тесты API и сборки Linux, Windows и iOS.

**Статус: MVP версии 0.6 для локальной разработки**, не готовая публичная identity-платформа. eNet ID пока самостоятельный, **не связан с аккаунтами Продайзера**. В приложении есть переход на `https://prodayzer.ru`, но нет интеграции его БД или платёжного баланса.

## Поддерживаемые платформы\n\n| Платформа | Сборка CI | Установка и запуск |\n|---|---|---|\n| Linux x64 | Да, готовый bundle | Архив из GitHub Actions, GTK/libsecret на системе |\n| Windows x64 | Да, готовый bundle | Архив из GitHub Actions; рядом с exe должны оставаться DLL и папка data |\n| iOS (iPhone) | Да, unsigned Runner.app | Для реальной установки нужна подпись Apple и provisioning profile; App Store требует Apple Developer Program |\n\n**iOS-сборка в CI не подписана** и не является готовым IPA для установки на iPhone. Это проверка компиляции и артефакт для последующей подписи. Bundle Identifier и сертификаты Apple необходимо согласовать перед публикацией.\n\n## Быстрый старт на Ubuntu

### 1. Скачать репозиторий

```bash
git clone https://github.com/enet-debug/enet-app.git
cd enet-app
```

После перевода репозитория в private потребуется аутентификация в GitHub.

### 2. Запустить eNet API

Нужен **Node.js 22.16+** (`node -v`).

```bash
cd api
npm test
node src/server.mjs
```

Проверка во втором терминале:

```bash
curl http://127.0.0.1:8787/health
```

Ожидаемый ответ: `{"status":"ok","service":"enet-api","version":"0.3.0"}`.
База данных будет создана в `api/data/enet.sqlite`. Доступ только с этого ПК по `127.0.0.1:8787`.

### 3. Запустить eNet APP на Ubuntu

После установки Flutter и Node.js также можно запустить оба компонента одной командой из корня проекта: `bash scripts/run-linux.sh`. Скрипт создаёт Linux runner при первом запуске, запускает локальный API при необходимости, затем Flutter APP.


Нужен Flutter SDK (Dart 3.6+). Зависимости для Linux:

```bash
sudo apt update
sudo apt install -y clang cmake ninja-build pkg-config libgtk-3-dev liblzma-dev libsecret-1-dev
cd ~/enet-app
flutter doctor -v
flutter config --enable-linux-desktop
flutter create --platforms=linux .
flutter pub get
flutter run -d linux --dart-define=ENET_API_URL=http://127.0.0.1:8787
```

Если репозиторий клонирован в другое место, замените `cd ~/enet-app` на путь к нему. `flutter create --platforms=linux .` генерирует нативный Linux-runner для стартового Flutter-проекта. В репозитории нет заранее собранных нативных папок.

**Без установки Flutter:** GitHub Actions собирает `enet-app-linux-x64` и, если сборка успешна, прикрепляет архив в разделе Actions. Распакуйте его на Ubuntu, сделайте `enet_app` исполняемым и запустите при включённом локальном API. Для бинарника также нужны системные GTK и libsecret-библиотеки.

## Запуск на Windows\n\nНа Windows 10/11 установи Node.js 22.16+ и Flutter SDK, открой PowerShell в папке репозитория и выполни:\n\n```powershell\nSet-ExecutionPolicy -Scope Process Bypass\n.\\scripts\\run-windows.ps1\n```\n\nСкрипт создаёт Windows runner при первом запуске, запускает локальный API и Flutter-клиент, а при завершении закрывает запущенный им API.\n\n## Запуск на iOS\n\nДля сборки и запуска нужен Mac с Xcode и Flutter. Физический iPhone не может обратиться к `127.0.0.1` на компьютере разработчика. Укажи публичный адрес API с HTTPS и запусти:\n\n```bash\nexport ENET_API_URL=https://твой-домен-api\nbash scripts/run-ios.sh\n```\n\nНа iOS экран входа позволяет изменить и сохранить адрес API. Удалённый HTTP блокируется; HTTP разрешён только для localhost при локальной разработке.\n\n## Настройка подключения

На одном ПК:

```bash
flutter run -d linux --dart-define=ENET_API_URL=http://127.0.0.1:8787
```

Если API работает на другом компьютере в локальной сети, необходимо:
- явно настроить `ENET_HOST` на сетевой адрес сервера;
- использовать корректный сетевой адрес в `ENET_API_URL`;
- защитить сеть и не публиковать такой HTTP-сервис в интернет.

Для подключения через интернет **обязательно HTTPS**, правильный DNS и обратный прокси. Не используйте простой HTTP для пользовательских паролей за пределами локального тестового окружения.

## Что уже работает

- Регистрация eNet ID с паролем от 12 символов;
- вход и выход, серверная проверка сессии, сохранение токена в защищённом хранилище ОС;
- профиль с именем и почтой, восстановление сессии после перезапуска приложения;
- каталог сервисов из API с обновлением и переходом на Продайзер прямо в приложении;
- проверка доступности API в настройках;
- смена пароля из приложения и закрытие сессий на остальных устройствах;
- изменение имени профиля через API с моментальным обновлением приложения;
- список активных сеансов и выборочное отключение отдельного устройства;
- автоматическая миграция старой SQLite-базы без удаления пользователей и сеансов;
- обновлённый дизайн с тёмно-изумрудной и мятной палитрой, обновлёнными карточками, шапкой и адаптивной навигацией;
- на главной: подтверждённый запросом к API статус сервера и быстрые переходы в профиль и настройки;
- поиск по названию и описанию сервисов с кнопкой очистки и адаптивными карточками;
- выбор анимации фона сохраняется на устройстве между перезапусками приложения;\n- адрес API можно настроить до входа, он сохраняется на устройстве; удалённые серверы допускаются только по HTTPS;\n- список активных сеансов показывает тип платформы клиента (Linux, Windows, iOS, macOS, Android);
- интеграционный тест API (команда `npm test`);
- GitHub Actions для проверки API и сборки Linux, Windows и iOS.

## Что пока НЕ сделано

- Подтверждение email и восстановление пароля через SMTP;
- единый вход в Продайзер, объединение пользователей, синхронизация объявлений и кредитов;
- размещение API на публичном сервере и настройка HTTPS (до этого iOS и удалённые клиенты не смогут подключаться к общей учётной записи);
- управление пользователями через административную панель (отзыв своих сеансов уже добавлен);
- дистрибуция deb/AppImage, автоматическое обновление, подпись;
- тесты Flutter на реальных устройствах Linux, Windows и iPhone;\n- подпись iOS-сборки и выпуск IPA;\n- автоматические обновления Windows и iOS.

Прежде чем запускать публично, необходимо добавить верификацию почты, восстановление пароля, MFA, централизованный rate limit для нескольких экземпляров API, резервное копирование, мониторинг и HTTPS. См. [документацию API](api/README.md).

Дизайн eNet APP версии 0.6 сохраняет исходную структуру и функциональность, но использует тёмный изумруд, мятные акценты и обновлённые сервисные карточки. Настройки внешних сервисов и секреты не хранятся в GitHub.

### Важно о дизайне и функциях

Главный экран не отображает выдуманные показатели: индикатор «eNet API отвечает» основан на запросе `GET /health`. Каталог получает реальные сервисы из `GET /v1/services`; поиск выполняется только по загруженным элементам, поэтому без соединения список изначально пуст. Динамический фон учитывает системное «уменьшить движение», а его ручное состояние сохраняется локально.
