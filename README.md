# eNet — Linux, Windows и iOS + eNet API

Монорепозиторий экосистемы eNet:

- `lib/`: Flutter-приложение для Linux, Windows и iOS с адаптивным интерфейсом.
- `api/`: локальный HTTP API с настоящими учётными записями, SQLite, сессиями и каталогом сервисов.
- `.github/workflows/enet-linux.yml`: интеграционные тесты API и автоматические сборки Linux, Windows и неподписанной iOS-версии.

**Статус: MVP версии 0.7 для разработки**, не готовая публичная identity-платформа. eNet ID пока самостоятельный, **не связан с аккаунтами Продайзера**. В приложении есть переход на `https://prodayzer.ru`, но нет интеграции его БД или платёжного баланса.

## Быстрый старт на Ubuntu

### 1. Скачать репозиторий

```bash
git clone https://github.com/enet-debug/enet-app.git
cd enet-app
```

После перевода репозитория в private потребуется аутентификация в GitHub.

### 2. Запустить eNet API

Нужен **Node.js 22.16+** (`node -v`).

```bash
cd api
npm test
node src/server.mjs
```

Проверка во втором терминале:

```bash
curl http://127.0.0.1:8787/health
```

Ожидаемый ответ: `{"status":"ok","service":"enet-api","version":"0.4.0"}`.
База данных будет создана в `api/data/enet.sqlite`. Доступ только с этого ПК по `127.0.0.1:8787`.

### 3. Запустить eNet APP на Ubuntu

После установки Flutter и Node.js также можно запустить оба компонента одной командой из корня проекта: `bash scripts/run-linux.sh`. Скрипт создаёт Linux runner при первом запуске, запускает локальный API при необходимости, затем Flutter APP.


Нужен Flutter SDK (Dart 3.6+). Зависимости для Linux:

```bash
sudo apt update
sudo apt install -y clang cmake ninja-build pkg-config libgtk-3-dev liblzma-dev libsecret-1-dev
cd ~/enet-app
flutter doctor -v
flutter config --enable-linux-desktop
flutter create --platforms=linux .
flutter pub get
flutter run -d linux --dart-define=ENET_API_URL=http://127.0.0.1:8787
```

Если репозиторий клонирован в другое место, замените `cd ~/enet-app` на путь к нему. `flutter create --platforms=linux .` генерирует нативный Linux-runner для стартового Flutter-проекта. В репозитории нет заранее собранных нативных папок.

**Без установки Flutter:** GitHub Actions собирает `enet-app-linux-x64` и, если сборка успешна, прикрепляет архив в разделе Actions. Распакуйте его на Ubuntu, сделайте `enet_app` исполняемым и запустите при включённом локальном API. Для бинарника также нужны системные GTK и libsecret-библиотеки.

## Настройка подключения

На одном ПК:

```bash
flutter run -d linux --dart-define=ENET_API_URL=http://127.0.0.1:8787
```

Если API работает на другом компьютере в локальной сети, необходимо:
- явно настроить `ENET_HOST` на сетевой адрес сервера;
- использовать корректный сетевой адрес в `ENET_API_URL`;
- защитить сеть и не публиковать такой HTTP-сервис в интернет.

Для подключения через интернет **обязательно HTTPS**, правильный DNS и обратный прокси. Не используйте простой HTTP для пользовательских паролей за пределами локального тестового окружения.

## Что уже работает

- Регистрация eNet ID с паролем от 12 символов;
- вход и выход, серверная проверка сессии, сохранение токена в защищённом хранилище ОС;
- профиль с именем и почтой, восстановление сессии после перезапуска приложения;
- каталог сервисов из API с обновлением и переходом на Продайзер прямо в приложении;
- проверка доступности API в настройках;
- смена пароля из приложения и закрытие сессий на остальных устройствах;
- изменение имени профиля через API с моментальным обновлением приложения;
- список активных сеансов и выборочное отключение отдельного устройства;
- автоматическая миграция старой SQLite-базы без удаления пользователей и сеансов;
- обновлённый дизайн с тёмно-изумрудной и мятной палитрой, обновлёнными карточками, шапкой и адаптивной навигацией;
- на главной: подтверждённый запросом к API статус сервера и быстрые переходы в профиль и настройки;
- поиск по названию и описанию сервисов с кнопкой очистки и адаптивными карточками;
- выбор анимации фона сохраняется на устройстве между перезапусками приложения;
- адрес eNet API выбирается в приложении до входа и в настройках;
- избранные сервисы синхронизируются между устройствами через аккаунт;
- события входа и приветственные уведомления хранятся в eNet ID, синхронизируются между клиентами, поддерживают отметки прочтения и отображаются в реальном центре уведомлений;
- `GET /ready` проверяет доступность SQLite, `GET /v1/meta` описывает возможности сервера;
- проверки сборок Windows x64 и iOS без Apple-подписи в GitHub Actions;
- интеграционный тест API (команда `npm test`);
- GitHub Actions для проверки API и сборок Linux, Windows и iOS.

## Что пока НЕ сделано

- Подтверждение email и восстановление пароля через SMTP;
- единый вход в Продайзер, объединение пользователей, синхронизация объявлений и кредитов;
- размещение API на публичном сервере и настройка HTTPS;
- управление пользователями через административную панель (отзыв своих сеансов уже добавлен);
- подписанные установщики Windows, iOS/TestFlight, автоматическое обновление;
- тесты Flutter на реальном Linux-компьютере пользователя.

Прежде чем запускать публично, необходимо усилить безопасность, добавить верификацию почты, централизованный rate limit и мониторинг. См. [документацию API](api/README.md).

## Структура

```
api/
  package.json
  src/app.mjs
  src/server.mjs
  test/api.test.mjs
lib/
  features/auth/      # API-клиент и UI eNet ID
  features/shell/     # главная, сервисы, профиль, настройки
.github/workflows/
  enet-linux.yml      # тесты и сборки Linux / Windows / iOS
```

Дизайн eNet APP версии 0.6 сохраняет исходную структуру и функциональность, но использует тёмный изумруд, мятные акценты и обновлённые сервисные карточки. Настройки внешних сервисов и секреты не хранятся в GitHub.

### Важно о дизайне и функциях

На телефонах блок быстрых действий прокручивается горизонтально, а главная карточка занимает меньше высоты. Главный экран не отображает выдуманные показатели: индикатор «eNet API отвечает» основан на запросе `GET /health`. Каталог получает реальные сервисы из `GET /v1/services`; поиск выполняется только по загруженным элементам, поэтому без соединения список изначально пуст. Динамический фон учитывает системное «уменьшить движение», а его ручное состояние сохраняется локально.

## Подготовка публичного API

Добавлены примеры конфигураций systemd, Caddy, переменных окружения и скрипт безопасного SQLite-бэкапа. Инструкция: [api/DEPLOYMENT.md](api/DEPLOYMENT.md). **Это подготовка инфраструктуры, а не факт развёртывания**: `api.enet-dev.ru` заработает только после настройки VPS, DNS и HTTPS.

Система ограничения числа запросов теперь учитывает отдельно попытки входа по IP и аккаунту; `Retry-After` сообщает время блокировки. Ограничения теперь сохраняются в SQLite и переживают перезапуск сервера. Для нескольких экземпляров и реальной эксплуатации потребуются общие лимиты, мониторинг и резервные копии.

## Windows 10/11

GitHub Actions собирает переносимую версию Windows `enet-app-windows-x64` с EXE и зависимостями. Для самостоятельной сборки требуются Flutter SDK и Visual Studio с компонентом Desktop development with C++:

```powershell
flutter config --enable-windows-desktop
flutter create --platforms=windows .
flutter pub get
flutter run -d windows
```

Без серверной части зарегистрироваться нельзя. Используйте локальный Node.js API на этом ПК либо укажите адрес удалённого HTTPS API на экране входа.

## iPhone и iOS

Код Flutter адаптирован под мобильные экраны. GitHub Actions на macOS выполняет `flutter build ios --release --no-codesign`. Это **проверка компиляции**, а не подписанное приложение для установки на iPhone. Для реального запуска нужен Mac с Xcode и Apple Developer-подпись, затем TestFlight или другой разрешённый Apple способ распространения.

Важное ограничение: `127.0.0.1` на iPhone обозначает **сам телефон**, а не Ubuntu-сервер. Перед входом пользователь должен указать работающий HTTPS API. Например, `https://api.enet-dev.ru` может стать таким адресом после фактического развёртывания, но пока он не подтверждён как действующий.

## Синхронизация и безопасность

Серверные настройки избранного доступны в `GET/POST /v1/me/preferences`. Каждый аккаунт имеет свой список, хранящийся в SQLite; неизвестные ID отклоняются. UI позволяет включать и выключать избранное на разных устройствах. Для удалённого API обязателен HTTPS. При смене адреса сервера клиент удаляет старую сессию и требует войти заново. Расширенный протокол описан в [API](api/README.md) и [OpenAPI](api/openapi.yaml).

Сейчас общий вход с Продайзером, SMTP-восстановление, публичное развёртывание и полноценная публикация iOS **не реализованы**.

## Центр уведомлений eNet 0.7

Раздел «Уведомления» теперь работает с реальным API (`GET /v1/notifications`, `POST /v1/notifications/read`, `POST /v1/notifications/read-all`). История и состояние прочтения связаны с eNet ID в SQLite. Новый интерфейс показывает только настоящие события, поддерживает обновление, ошибки сети и мобильные экраны. В главном разделе появился быстрый переход к этой истории. Для синхронизации между компьютером и iPhone API нужно развернуть на HTTPS-сервере, локальный `127.0.0.1` телефона для этого не подходит.
