# eNet — приложение для Linux + API + eNet ID

Монорепозиторий экосистемы eNet:

- `lib/`: Flutter-приложение с адаптивным интерфейсом для Linux и других платформ.
- `api/`: локальный HTTP API с настоящими учётными записями, SQLite, сессиями и каталогом сервисов.
- `.github/workflows/enet-linux.yml`: интеграционные тесты API и сборка Linux-приложения.

**Статус: MVP для локальной разработки**, не готовая публичная identity-платформа. eNet ID пока самостоятельный, **не связан с аккаунтами Продайзера**. В приложении есть переход на `https://prodayzer.ru`, но нет интеграции его БД или платёжного баланса.

## Быстрый старт на Ubuntu

### 1. Скачать репозиторий

```bash
git clone https://github.com/enet-debug/enet-app.git
cd enet-app
```

После перевода репозитория в private потребуется аутентификация в GitHub.

### 2. Запустить eNet API

Нужен **Node.js 22.16+** (`node -v`).

```bash
cd api
npm test
node src/server.mjs
```

Проверка во втором терминале:

```bash
curl http://127.0.0.1:8787/health
```

Ожидаемый ответ: `{"status":"ok","service":"enet-api","version":"0.1.0"}`.
База данных будет создана в `api/data/enet.sqlite`. Доступ только с этого ПК по `127.0.0.1:8787`.

### 3. Запустить eNet APP на Ubuntu

Нужен Flutter SDK (Dart 3.6+). Зависимости для Linux:

```bash
sudo apt update
sudo apt install -y clang cmake ninja-build pkg-config libgtk-3-dev liblzma-dev libsecret-1-dev
cd ~/enet-app
flutter doctor -v
flutter config --enable-linux-desktop
flutter create --platforms=linux .
flutter pub get
flutter run -d linux --dart-define=ENET_API_URL=http://127.0.0.1:8787
```

Если репозиторий клонирован в другое место, замените `cd ~/enet-app` на путь к нему. `flutter create --platforms=linux .` генерирует нативный Linux-runner для стартового Flutter-проекта. В репозитории нет заранее собранных нативных папок.

**Без установки Flutter:** GitHub Actions собирает `enet-app-linux-x64` и, если сборка успешна, прикрепляет архив в разделе Actions. Распакуйте его на Ubuntu, сделайте `enet_app` исполняемым и запустите при включённом локальном API. Для бинарника также нужны системные GTK и libsecret-библиотеки.

## Настройка подключения

На одном ПК:

```bash
flutter run -d linux --dart-define=ENET_API_URL=http://127.0.0.1:8787
```

Если API работает на другом компьютере в локальной сети, необходимо:
- явно настроить `ENET_HOST` на сетевой адрес сервера;
- использовать корректный сетевой адрес в `ENET_API_URL`;
- защитить сеть и не публиковать такой HTTP-сервис в интернет.

Для подключения через интернет **обязательно HTTPS**, правильный DNS и обратный прокси. Не используйте простой HTTP для пользовательских паролей за пределами локального тестового окружения.

## Что уже работает

- Регистрация eNet ID с паролем от 12 символов;
- вход и выход, серверная проверка сессии, сохранение токена в защищённом хранилище ОС;
- профиль с именем и почтой, восстановление сессии после перезапуска приложения;
- каталог сервисов в API, ссылка на Продайзер в приложении;
- интеграционный тест API (команда `npm test`);
- GitHub Actions для проверки API и Linux-сборки.

## Что пока НЕ сделано

- Подтверждение email и восстановление пароля через SMTP;
- единый вход в Продайзер, объединение пользователей, синхронизация объявлений и кредитов;
- размещение API на публичном сервере и настройка HTTPS;
- управление пользователями через административную панель;
- дистрибуция deb/AppImage, автоматическое обновление, подпись;
- тесты Flutter на реальном Linux-компьютере пользователя.

Прежде чем запускать публично, необходимо усилить безопасность, добавить верификацию почты, централизованный rate limit и мониторинг. См. [документацию API](api/README.md).

## Структура

```
api/
  package.json
  src/app.mjs
  src/server.mjs
  test/api.test.mjs
lib/
  features/auth/      # API-клиент и UI eNet ID
  features/shell/     # главная, сервисы, профиль, настройки
.github/workflows/
  enet-linux.yml      # тесты и сборка Linux
```

Интерфейс eNet APP сохраняет существующий дизайн; настройки внешних сервисов и секреты не хранятся в GitHub.
